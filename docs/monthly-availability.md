# 當月時段批次查詢

每次進入月份只發一個 getMonthAvailability&month=YYYY-MM 請求。後端讀取預約 E:H 一次、公休日一次、設定一次；將有效占位整理為索引後計算月份內可預約日期的 12 個時段。只回傳時段狀態，不回傳客戶資料。

前端首次開站載入當月資料及設定；切月份預載新月份。60 秒內切日期使用記憶體資料，不再呼叫每日時段 API。重複載入同月份共用同一個進行中請求。超過 60 秒，在下次需要資料時重新查詢。已預約時段仍停用。所有送出結果使該月快取失效；空位衝突時重新載入。正式提交仍使用既有鎖與最新試算表資料，未改為依賴快取。

## 部署

1. 將本次 backend/code.js 完整更新到既有 Apps Script 專案。
2. 更新目前 AKfycbxlh… Web App 的部署版本，保留相同網址。
3. GET `?action=getMonthAvailability&month=2026-10` 應回 status=ok、month、days、settings、holidays。
4. 部署完成後先量測月查詢及核對每日查詢一致性，再合併前端 PR。

舊每日 GET API 保留；POST 的安全檢查不變。新版前端需要新版月 API，故不可先發布前端。

## 量測與限制

2026-10-12 修改前正式網站：日期點擊到時段顯示 2.99～5.53 秒，平均 4.17 秒；每日時段 API 六次平均 3.62 秒。

修改後：隔離瀏覽器測試驗證已載入月份的日期點擊不發送請求；記憶體時段整理／DOM 建立在五次測試為 0～2 毫秒（本機 Edge，測試 API）。這不是 Google 端新版首次月載入耗時，也不包含實際螢幕繪製；不能把它稱作正式端到端量測。

新版月 API 的正式延遲尚待 Apps Script 部署後量測。36 項後端測試通過，包含月／每日結果相同、日期範圍、公休日、E:H 只讀一次及客戶資料不回傳。瀏覽器测试涵蓋月份快取、過期更新、月份切換、衝突更新及既有預約流程。

快取可能在 60 秒內短暫落後其他客人預約／管理者修改，正式送出會重新檢查並拒絕失效空位。已釋放時段最多需等到再次刷新月資料才顯示可選。
